# 02. 요구사항 명세

## 1. 용어

| 용어 | 뜻 |
| --- | --- |
| 맨데이트(mandate) | 펀드 설계서. 전략·애널리스트·리스크·자본·리밸런싱 주기. **종목은 없음** |
| 유니버스(universe) | 맨데이트를 겨눌 종목 목록. 백테스트/배치 시점에 지정 |
| 전략(strategy, pod) | 애널리스트 묶음 + 블렌드 정책(long_only / long_short / dollar_neutral) |
| 애널리스트 모델 | 신호(-1~+1)와 논거를 내는 주체. LLM 에이전트(버핏·멍거·그레이엄·린치·드러켄밀러) 또는 퀀트(PEAD) |
| 세션(session) | 완료된 거래일 하루. T일 종가에 내린 결정은 T+1 종가에 체결 |
| 원장(ledger) | 세션별 `SessionRecord`를 해시 체인으로 이어 붙인 append-only 기록 |

## 2. 기능 요구사항

### FR-1 설정
- FR-1.1 현재 모드(demo/live), 선택된 LLM 모델, 키 등록 여부(마스킹)를 조회한다.
- FR-1.2 키를 등록하면 `~/.hedge-fund/.env`에 저장된다(업스트림 `save_credential` 사용, 권한 0600). 키 원문은 다시 반환하지 않는다.
- FR-1.3 live 전환은 데이터 키가 있어야 가능하다. LLM 키가 없으면 경고(LLM 에이전트가 포함된 실행은 거부).
- FR-1.4 키가 하나도 없으면 최초 모드는 demo.

### FR-2 카탈로그
- FR-2.1 애널리스트 목록(이름, 표시명, 종류 llm/quant, 접근법, 평가 지평).
- FR-2.2 전략 라이브러리(패키지 내 YAML)와 설명.
- FR-2.3 LLM 모델 레지스트리, 유니버스 프리셋, 기본 리스크/자본 값.

### FR-3 맨데이트
- FR-3.1 목록: 이름, 전략 요약, 자본, 주기, 벤치마크, 최근 백테스트 성과. 깨진 YAML은 오류와 함께 표시.
- FR-3.2 생성: 라이브러리 전략 선택 또는 애널리스트 직접 조합(custom), 전략별 자본 비중, 리스크 한도, 자본, 주기(daily/weekly/monthly), 벤치마크. 서버가 `FundSpec`으로 검증하고 오류를 필드 경로와 함께 돌려준다.
- FR-3.3 동일 이름 덮어쓰기 금지(409). 삭제 가능.

### FR-4 백테스트
- FR-4.1 입력: 맨데이트, 유니버스(1개 이상), 시작/종료일(기본: 최근 260일).
- FR-4.2 비동기 작업으로 실행하고 진행률(세션 n/N)과 중간 곡선을 조회할 수 있다.
- FR-4.3 결과: 총수익·연환산·샤프·MDD·벤치마크·초과수익·리밸런싱 수·주문 수·거래비용, NAV/벤치마크 곡선, 낙폭 곡선, 리밸런싱(체결) 목록, 최종 포지션, 성적표(애널리스트 적중률·IC, 전략 P&L).
- FR-4.4 드릴다운: 세션 하나의 결정(전략별 신호·논거, 목표/최종 비중, 클램프)과 체결(주문·체결가·비용).
- FR-4.5 결과는 업스트림과 같은 형식으로 `research/`에 저장되고 목록·삭제가 가능하다.
- FR-4.6 live 백테스트는 업스트림과 동일하게 블라인드 프롬프트(`blind=True`)로 실행한다.

### FR-5 페이퍼 트레이딩
- FR-5.1 배치: 펀드 이름 + 맨데이트 + 유니버스. 이름 규칙·중복은 서버가 검증.
- FR-5.2 목록/상세: NAV·수익률·세션 수·마지막 세션·정지 여부, 포지션(수량·평가액·비중), 대기 중 결정, NAV 이력, 이벤트 로그.
- FR-5.3 미리보기: 다음에 실행될 세션과, 그 세션에서 체결될 대기 결정을 보여 준다(승인 단계).
- FR-5.4 실행: 세션 1개 또는 최대 N개 연속 전진(밀린 세션 따라잡기). 세션은 건너뛰지 않는다.
- FR-5.5 킬 스위치: 사유와 함께 정지, 재개. 실행 실패 시 엔진이 자동 정지시키며 사유를 표시.
- FR-5.6 세션 드릴다운·성적표는 백테스트와 동일한 화면 구성.
- FR-5.7 (데모 한정) 새 펀드는 90일 전부터 시작해, 하루를 기다리지 않고도 세션을 넘겨 볼 수 있다.

### FR-6 대시보드
- 모드, 준비 상태, 맨데이트/백테스트/펀드 수, 최근 백테스트 5건, 펀드별 NAV 요약.

## 3. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 정합성 | 엔진 계산은 전부 `aihf` 호출. 웹 계층은 지표를 재계산하지 않는다(낙폭 곡선처럼 표시용 파생값 제외). |
| NFR-2 동시성 | 엔진 작업은 단일 워커 큐로 직렬화 — 같은 원장에 두 틱이 겹치지 않는다. |
| NFR-3 보안 | 기본 `127.0.0.1` 바인딩, CORS는 개발 서버 오리진만, 키 원문 미반환, 경로 파라미터는 이름 규칙 검증(디렉터리 탈출 방지). |
| NFR-4 격리 | demo 저장소(`~/.hedge-fund/web-demo/`)와 live 저장소(`~/.hedge-fund/`)는 분리. |
| NFR-5 응답성 | 조회 API는 원장 파일만 읽어 즉시 응답. 네트워크가 필요한 호출(미리보기·실행)은 분리. |
| NFR-6 접근성/반응형 | 라이트/다크 테마, 모바일 폭(≥360px)에서 가로 스크롤 없이 사용. |
| NFR-7 설치 | `uv sync` + `npm ci && npm run build` + 단일 프로세스(`uvicorn`)로 UI까지 서빙. |
| NFR-8 테스트 | 백엔드 pytest(데모 엔진으로 전 엔드포인트), 프런트 타입체크/빌드, 브라우저 E2E 스모크. |
