# 09. 무료 데이터 어댑터

유료 키(Financial Datasets) 없이 실제 종목으로 엔진을 돌려 보는 `free` 모드의 설계와 한계.

## 왜 EDGAR + Yahoo인가

엔진의 첫 원칙은 **시점 정합**(그날 공개된 데이터만 본다)이다. 무료 소스 대부분은 재무를 "현재 기준 최신값"으로만 주어 백테스트에 미래 정보가 섞인다.
SEC EDGAR의 XBRL `companyfacts`는 항목마다 `filed`(공시 제출일)를 갖고 있어, 무료 소스 중 유일하게 이 원칙을 지킬 수 있다.
시세는 EDGAR에 없으므로 Yahoo 차트 엔드포인트를 쓴다(비공식).

## 구성

```
engine/free/edgar.py    Filings — companyfacts → 시점 기준 TTM 재무 행(FinancialMetrics)
engine/free/client.py   FreeDataClient — DataClient 구현: SEC/Yahoo 호출, 디스크 캐시, 호출 간격
```

- **TTM 재구성**: 플로 항목은 `최근 누적(YTD) + 직전 회계연도 − 전년 동기 YTD`, 잔액 항목은 기말 값. 사업연도 말은 연간 값 그대로.
- **시점 규칙**: `filed <= as_of`인 사실만 사용. 같은 기간이 나중에 정정되면 그날까지 알려진 값을 쓴다. 보고기간의 공시일은 같은 기간 중 가장 이른 제출일.
- **시장가 파생 지표**: P/E·시총은 공시일 종가 × 공시 표지의 발행주식수로 계산.
- **캐시**: `~/.hedge-fund/web-free/cache/free/` (공시 1일, 티커표·기업정보 7일, 시세 12시간).
- **SEC 정책**: 실제 연락처가 담긴 User-Agent(필수, 설정에서 입력)와 요청 간격 0.15초. 403이면 가짜 값으로 재시도하지 않고 오류를 그대로 올린다.

## 한계 (화면의 `notes`와 같은 내용)

| 항목 | 상태 |
| --- | --- |
| 재무 정확도 | XBRL 태그 별칭으로 재구성한 근사값. 태그를 안 쓰는 회사·지표는 None. 총부채는 장기부채 + 대표적 단기 항목 |
| 시세 | 분할 조정, 배당 미조정. 비공식 엔드포인트 |
| 실적 서프라이즈 | 추정치가 없어 `get_earnings_history`는 빈 값 → **PEAD 모델 무신호** |
| 뉴스·내부자·스크리너 | 없음(스크리너는 호출 시 오류) |
| 섹터 | SIC 코드 기반 거친 분류. 섹터 한도를 쓰면 정밀도가 낮다 |
| ETF·비SEC 종목 | 시세만 있고 재무는 빈 값(예: SPY는 벤치마크로만 사용) |

## 검증

- 단위(오프라인): 실제 AAPL 응답을 줄인 픽스처로 12건 — 공시일 전날은 안 보이고 당일엔 보임, 사업연도 TTM = 연간 값(937.36억 달러), 3분기 TTM = 9개월 + 직전 연도 − 전년 9개월, 정정값 시점 처리, 비율 범위, 디스크 캐시, 연락처 필수·전송.
- 통합: 가짜 EDGAR/Yahoo로 백테스트 전 과정 — 에이전트가 실제 AAPL 재무를 읽고, 리포트에 한계 노트가 붙고, 데모 저장소와 섞이지 않음.
- 실응답: Yahoo 파서를 AAPL·SPY·BRK-B 실제 응답으로 확인(2005년 AAPL 분할 조정 종가 $1.13), 없는 티커는 빈 결과.
- **미검증: 실제 SEC 호출.** 연락처를 입력받지 못해 EDGAR에는 요청하지 않았다.
